# Как разобраться в проекте

Начните с запуска. Создайте одну вымышленную заявку, откройте карточку и поменяйте статус. После этого код будет проще связать с тем, что видно на экране.

## Что сказать о проекте

Смысл проекта: собрать известные сведения о семье в одном месте и подготовить обращение в архив. В нём три основные страницы: список заявок, форма создания и карточка. Python обрабатывает данные, SQLite хранит их, HTML и CSS показывают интерфейс.

Рассказывайте о тех действиях, которые уже повторили сами. Проект подготовлен с помощью AI; на вопрос об этом можно прямо объяснить, какие части вы разобрали, проверили и изменили. Не нужно выдавать шаблон письма за работающую нейросеть или говорить о коммерческом использовании.

## Что происходит при нажатии кнопки

1. В `form.html` у формы стоит `method="post"`. Браузер отправляет значения полей серверу.
2. В `app.py` адрес `/requests/new` связан с функцией `new_request`.
3. `request.form` содержит отправленные поля.
4. `validate_request` из `services.py` убирает пробелы по краям и проверяет длину.
5. Если есть ошибки, `render_template` снова показывает форму. Код ответа 422 означает ошибку в содержимом запроса.
6. Если данные подходят, SQL-команда `INSERT` записывает их в таблицу `requests`.
7. Сервер возвращает перенаправление 303. Браузер открывает карточку через GET.
8. `make_draft` получает запись и составляет письмо. Никакой отправки наружу нет.

## Прочитать в таком порядке

### 1. services.py

`LIMITS` хранит допустимую длину. Например, описание должно содержать от 20 до 2000 символов.

`validate_request` возвращает два словаря: очищенные значения и ошибки. Разделение полезно: интерфейс показывает введённые данные рядом с конкретной ошибкой.

`make_draft` собирает строку из нескольких частей. Конструкция `f"Место: {data['region']}"` подставляет значение поля в текст. Если период пустой, в письме появляется просьба уточнить его.

### 2. app.py

`create_app` создаёт приложение. Это функция, чтобы тесты могли запускать отдельный экземпляр с временной базой.

`@app.get('/')` связывает адрес главной страницы с функцией `index`.

`connect` открывает SQLite. `row_factory` позволяет обращаться к колонке по имени: `row['person']`.

В SQL стоят знаки `?`, а значения передаются отдельно. Поэтому введённый текст не превращается в SQL-команду.

`session` хранит идентификатор браузера и токен формы. Это подписанная cookie, а не полноценная учётная запись. Имена и описания заявок хранятся в SQLite.

`owned_request` получает заявку только для текущей сессии. Чужой номер в адресной строке возвращает 404.

### 3. HTML

`base.html` содержит общую шапку, стили и нижнюю часть страницы. Остальные шаблоны используют его через `extends`.

`{{ row.person }}` выводит значение, а `{% for ... %}` повторяет разметку для списка записей.

Jinja экранирует HTML. Введённый пользователем `<script>` показывается текстом и не выполняется.

### 4. CSS и JavaScript

CSS задаёт оформление. Grid размещает блоки в колонках. В `@media(max-width:760px)` страницы переходят к одной колонке.

JavaScript обновляет счётчик, проверяет пробелы в обязательных полях, блокирует кнопку во время отправки и копирует письмо.

Сайт сохраняет заявки без JavaScript: серверная проверка остаётся. Счётчик и автоматическое копирование при этом не работают.

## Вопросы на собеседовании

| Вопрос | Короткий ответ |
| --- | --- |
| Что такое Flask? | Небольшой веб-фреймворк Python: принимает запросы и возвращает ответы |
| Что такое маршрут? | Связь адреса сайта с функцией Python |
| Чем отличаются GET и POST? | GET получает страницу, POST отправляет данные для изменения |
| Где хранятся заявки? | В файле `instance/archive.sqlite` |
| Почему SQLite? | Для небольшого локального проекта достаточно базы в одном файле |
| Зачем проверять на сервере? | Проверки браузера можно обойти, сервер должен сам проверять данные |
| Как защищён двойной клик? | У формы уникальный идентификатор; повтор того же POST не создаёт вторую запись |
| Что такое CSRF-токен? | Случайное значение, которое связывает отправленную форму с сессией браузера |
| Почему после POST идёт 303? | Чтобы обновление карточки повторяло GET, а не отправляло форму заново |
| Есть ли AI внутри сервиса? | Нет. Письмо собирается по шаблону. AI использовался при подготовке проекта |
| Как тестировали? | Flask test client отправляет запросы, pytest проверяет ответы и базу |
| Что ещё нужно для реальной работы? | Авторизация, роли, восстановление доступа, HTTPS и правила хранения данных |

## Показ за три минуты

1. Главная: «Здесь список запросов и фильтр по статусу».
2. Форма: введите «Соколовы», «Саратовская губерния», оставьте период пустым.
3. Описание: «По семейным воспоминаниям жили в селе. Точное название пока неизвестно».
4. Сохраните: «Заявка записалась в базу. Неизвестную дату сервис не придумал».
5. Покажите письмо и кнопку копирования.
6. Поставьте статус «В работе», вернитесь к списку и включите соответствующий фильтр.
7. Откройте `services.py` и покажите одну понятную функцию.

## Что сделать самому перед разговором

- Поменять заголовок формы и объяснить, в каком файле он находится.
- Изменить цвет кнопки через переменную `--accent`.
- Добавить одну строчку в шаблон письма и показать результат.
- Запустить тесты и объяснить одну проверку.
- Создать заявку с пробелами вместо имени и проверить сообщение.

После этих действий у вас будут свои небольшие изменения и наблюдения, о которых можно рассказать без заучивания.

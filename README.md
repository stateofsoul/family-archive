# Семейный архив

Небольшой сервис на Python и Flask для подготовки архивных запросов. Можно записать известные сведения о семье, получить черновик обращения и отметить, на каком этапе находится поиск.

Проект учебный. В примерах используются вымышленные сведения. Он не связан с реальным генеалогическим центром и не отправляет письма в архивы.

## Что можно сделать

- Создать заявку с именем, местом, периодом и описанием.
- Получить сообщения об ошибках, сохранив заполненные поля.
- Посмотреть свои заявки и отфильтровать их по статусу.
- Поменять статус: новая, в работе, завершена.
- Скопировать черновик обращения, составленный по шаблону.
- Открыть интерфейс на небольшом экране.

## Запуск на Windows

Нужен Python 3.10 или новее. Самый простой способ: распаковать проект и дважды нажать `START_WINDOWS.bat`. При первом запуске нужен интернет для установки Flask. Затем открыть http://127.0.0.1:5000.

Ручной вариант: откройте терминал в папке, где лежит `app.py`.

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000. Пока работает сайт, оставьте терминал открытым. Для остановки нажмите Ctrl+C.

Если команда `py` не найдена, замените её на `python`. В Git Bash путь к интерпретатору выглядит так: `.venv/Scripts/python.exe`.

## Запуск на Linux и macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

## Проверки

На Windows:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

На Linux и macOS используйте `.venv/bin/python`. В наборе 22 проверки: создание заявки, границы полей, повторная отправка, смена статуса, изоляция сессий, экранирование HTML, сохранение после перезапуска.

Дополнительно, если установлен Node.js: `node tests/test_frontend.mjs`. Это проверка JavaScript с заглушками, без настоящего браузера.

## Как устроен код

| Файл | За что отвечает |
| --- | --- |
| `app.py` | Адреса страниц, чтение формы, запросы к SQLite, сессия браузера |
| `services.py` | Проверка полей и сборка текста обращения |
| `templates/` | HTML-страницы с шаблонами Jinja |
| `static/style.css` | Цвета, размеры, сетка и адаптивная вёрстка |
| `static/app.js` | Счётчик текста, проверка пробелов, копирование |
| `tests/test_app.py` | Автоматические проверки |
| `docs/EXPLAIN.md` | Разбор кода и вопросы для самостоятельной подготовки |
| `docs/CHECKLIST.md` | Сценарии ручной проверки |

## Один запрос от начала до конца

Браузер отправляет форму через POST. Flask читает поля и передаёт их в `validate_request`. При ошибке возвращается форма с сообщением. Если всё хорошо, запись сохраняется в SQLite, а браузер переходит на страницу заявки. Функция `make_draft` подставляет исходные сведения в шаблон письма.

## Почему такой стек

Flask позволяет собрать небольшой сайт без отдельного фронтенд-приложения. SQLite хранит данные в одном файле и не требует установки сервера. HTML, CSS и обычного JavaScript достаточно для трёх страниц.

AI API не подключён. Текст собирается по шаблону, поэтому неизвестные даты и архивные факты не придумываются. Примеры задач для работы с AI при доработке лежат в `docs/PRACTICE.md`.

## Ограничения

Это локальная демонстрация, а не готовая рабочая система. Заявки привязаны к сессии браузера. Если удалить cookie, прежние заявки останутся в базе, но перестанут отображаться. Входа по логину, ролей сотрудников, восстановления доступа, редактирования и удаления заявок пока нет.

Данные и локальный ключ появляются в `instance/`; эта папка исключена из Git. Не используйте реальные персональные данные. Перед публичным запуском потребуются полноценная авторизация, HTTPS, сервер для продакшена и правила хранения данных.

Следующее небольшое улучшение: редактирование заявки с повторной проверкой полей.
